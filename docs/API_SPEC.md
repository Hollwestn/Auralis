# Auralis API v1

Базовый путь: `http://127.0.0.1:8080/api/v1`; на VPS используйте HTTPS. UTF-8 JSON, идентификаторы UUID, даты ISO-8601 UTC. Каталог и все объекты принадлежат аккаунту; чужой ID возвращает 404. Музыка не появляется автоматически: нужен явный upload или разрешённый администратором импорт. Начальная БД пуста.

OpenAPI 3.0: общий контракт `shared/api-contracts/openapi.yaml`; серверная JSON-копия `backend/server/src/main/resources/static/openapi.json`, после запуска — `GET /openapi.json`. Файлы описывают действующие маршруты; интерактивный Swagger UI не включён.

## Авторизация

`POST /auth/register`: `{ "email":"you@example.com", "password":"пароль от 10 до 128 символов", "displayName":"Имя" }`.

`POST /auth/login`: `{ "email":"you@example.com", "password":"..." }`.

Оба возвращают `{ "token":"непрозрачный bearer token", "user":{ "id":"uuid", "email":"...", "displayName":"..." } }`. Срок токена — 30 дней. В БД хранится SHA-256 токена; пароль — PBKDF2-HMAC-SHA256 с индивидуальной солью (Spring Security v5.8 defaults, 310000 итераций). Передавайте `Authorization: Bearer TOKEN` во всех запросах кроме health/register/login и статического OpenAPI. Не помещайте токен в URL. Сохраняйте его в защищённом хранилище устройства.

- `POST /auth/logout`: отозвать текущий токен.
- `GET /account`: текущий `{id,email,displayName}`.
- `DELETE /account`: удалить аккаунт, токены, пользовательские записи и загруженные серверные копии. Локальные оригиналы не затрагиваются.
- `GET /health`: `{status:"ok",service:"auralis",apiVersion:"1"}`; проверяет SQL-соединение.

## Каталог и поток

`GET /tracks?q=&offset=0&limit=200` возвращает массив Track. `limit` 1–1000; пустой массив означает конец страницы. Поиск по названию, исполнителю и альбому, без учёта регистра. `%` и `_` — буквальные символы.

```json
{
  "id":"uuid", "title":"Название", "artist":"Исполнитель", "album":"Альбом", "genre":"Ambient",
  "durationSeconds":180.0, "sizeBytes":1234567, "mimeType":"audio/flac", "source":"SERVER", "coverUrl":null
}
```

- `GET /tracks/{id}`: Track.
- `DELETE /tracks/{id}`: удалить трек и серверную копию, ссылки из плейлистов/истории удаляются каскадно.
- `POST /catalog/upload`: multipart `file` + необязательные поля `title`, `artist`, `album`, `genre`. Поддерживаемые контейнеры: MP3, FLAC, WAV, OGG, M4A, AIFF. Максимум 300 МБ; содержимое разбирает Jaudiotagger, неверное аудио получает 400. Теги читаются из файла, поля запроса их переопределяют. SHA-256 предотвращает дубликаты в аккаунте; повторная загрузка возвращает существующий Track. Квота по умолчанию 20 ГиБ аудио/аккаунт.
- `GET /tracks/{id}/cover` (также HEAD): настоящая встроенная PNG/JPEG, максимум 5 МиБ и 2048 пикселей по каждой стороне. Декодер проверяет тип и размеры; произвольные MIME/HTML/SVG и слишком большие изображения не публикуются. Требуется bearer владельца; без него 401, чужой трек/отсутствующая обложка — 404. `coverUrl` — путь от корня сервера, например `/api/v1/tracks/uuid/cover`, только при фактической обложке; иначе null. Клиент добавляет свой URL сервера и Authorization. Ответ содержит image/png или image/jpeg, Content-Length, X-Content-Type-Options: nosniff, Cache-Control: private. Извлечение и кэширование происходят при чтении метаданных/первом обращении, включая старые треки. Отсутствие кэшируется; оригинальное аудио не меняется. При удалении трека/аккаунта кэш очищается.
- `POST /catalog/import`: `{ "path":"relative-folder" }` → `{ "tracks":[Track], "rejected":["filename: причина"] }`. Доступно только неизменяемому ID аккаунта из `AURALIS_IMPORT_ADMIN_USER_ID` и внутри `AURALIS_IMPORT_ROOT`. ID берётся из ответа регистрации или `GET /account`; оба параметра по умолчанию пусты. Email не предоставляет полномочий. Повторная регистрация после удаления создаёт новый ID без доступа к папке. Рекурсивно копирует распознанные файлы в приватное хранилище; оригиналы сохраняются. Path traversal и выход через символьные ссылки запрещены. Импорт синхронный, до 10000 просмотренных файлов за запрос; UI должен запускать его вне основного потока. Большую коллекцию импортируйте подпапками.
- `GET /tracks/{id}/stream`, `HEAD` того же URL: оригинальный файл без перекодирования. Header `Range: bytes=START-END`, `bytes=START-` или `bytes=-N`; 206 + `Content-Range`, полный файл 200; ошибочный/множественный range 416 + `Content-Range: bytes */SIZE`. `Accept-Ranges: bytes`, ETag по содержимому; `If-Range` с совпавшим ETag разрешает range. Буфер передачи 64 КиБ. Токен обязателен для каждого запроса. Поддержка кодека зависит от клиента.

## Библиотека

- `GET /favorites` → Track[]. `PUT /favorites/{trackId}` добавить, `DELETE` удалить. PUT идемпотентен.
- `GET /playlists` → `[{id,name,trackIds:["uuid"],updatedAt:"ISO",version:1}]`.
- `POST /playlists`: `{name,trackIds?:[]}` → Playlist.
- `PUT /playlists/{id}`: `{name,trackIds:[],version?:1}` → Playlist. Полная атомарная замена имени/очереди; порядок сохраняется, дубликаты допустимы. При указанной устаревшей version возвращается 409, данные остаются прежними. Старые клиенты без version совместимы, но должны перейти на версионную запись для защиты изменений другого устройства. Отсутствующий `trackIds` означает пустой плейлист. До 10000 треков; чужие ID запрещены.
- `DELETE /playlists/{id}`.
- `GET /history?limit=200&offset=0` → `[{id,trackId,playedSeconds,completed,skipped,playedAt,eventId}]`, новые первыми, `limit` 1–1000.
- `POST /history`: `{trackId,playedSeconds,completed,skipped,eventId?,playedAt?}`. Секунды ≥0 и ≤86400; при известной длительности не более duration+5. Событие отправляется клиентом после фактического прослушивания. Необязательный eventId — стабильный ключ `[A-Za-z0-9._:-]`, 1–100 символов, уникальный внутри аккаунта. Повтор той же записи с тем же ключом возвращает исходное событие без дубликата; другой payload с этим ключом получает 409. Ключ нужно создавать при постановке в локальную очередь и сохранять при повторе. playedAt сохраняет исходное время (не ранее 1970 и максимум на 5 минут в будущем), с точностью до микросекунд; без поля используется серверное время. Старый формат остаётся совместимым.
- `DELETE /history`: удалить всю историю аккаунта.
- `GET /preferences`, `PUT /preferences` → `{genres:["Ambient"],artists:["Имя"]}`. PUT полностью заменяет предпочтения, до 100 значений в списке.
- `POST /feedback`: `{trackId,action}`; action `LIKE`, `DISLIKE`, `MORE`, `LESS`, `BLOCK_ARTIST`, `UNBLOCK_ARTIST`. Последняя реакция на трек заменяет предыдущую; блокировка исполнителя хранится отдельно.

## Волна

`GET /wave?mode=MY_WAVE&limit=30` → `[{track:Track,score:8.4,reasons:["Ваш интерес к жанру «Ambient»"]}]`.

Режимы: `MY_WAVE`, `DISCOVERY`, `FAVORITES`, `FOCUS`, `ENERGY`, `NIGHT`, `RELAX`, `FAMILIAR`; limit 1–100. Пустая библиотека/полная блокировка возвращает `[]`. Алгоритм ранжирует только собственный серверный каталог; учитывает жанры/исполнителей, лайки, избранное, долю прослушивания, повторы и мягкий сигнал пропуска. Недавние повторы получают штраф, выдача балансирует исполнителей. DISLIKE и блокировка исключают кандидатов. Режимы настроения используют текстовые теги жанра, аудиоэнергия/BPM не анализируются. Cold start честно объясняется в reasons.

## Синхронизация

`GET /sync` → `{version:0,settings:{},playback:{},updatedAt:"ISO"}`.

`PUT /sync`: `{version:0,settings:{theme:"Jade",advancedMode:false},playback:{trackId:"uuid",positionSeconds:12.5,queue:["uuid"],queueIndex:0,playing:false,shuffle:false,repeat:"OFF"}}` → тот же объект с версией +1. `settings` и `playback` — JSON-объекты до 64 КиБ UTF-8 каждый; дополнительные поля сохраняются. Сервер проверяет принадлежность `trackId` и всех элементов `queue` (до 1000), неотрицательную позицию, типы playing/shuffle и repeat OFF/ALL/ONE. Если передан queueIndex, он должен указывать на выбранный trackId, включая повторные вхождения трека; пустая очередь требует индекса -1 и null trackId. Старые клиенты могут не передавать queueIndex. Состояние заменяется целиком. При устаревшей версии — 409: получите свежий GET, объедините нужные изменения, повторите PUT. Синхронизация выполняется запросами клиентов; push/WebSocket не реализованы. Плейлисты, избранное, история и предпочтения уже общие для аккаунта и читаются соответствующими GET.

## Ошибки и ограничения

Ответ контролируемой ошибки: `{ "error":"Описание на русском" }`. Статусы: 400 формат/валидация, 401 вход, 403 запрещённый импорт, 404 объект, 409 конфликт, 413 размер/квота, 416 range, 429 лимит. Лимит с IP сокета: 20 auth-запросов и 1000 прочих API-запросов в минуту; `Retry-After: 60`. За одним reverse proxy лимит разделяется между его клиентами. Клиентам нужен backoff. Публичный API без cookies; CORS для браузерных приложений не включён.

Первая реализация предназначена для персонального сервера с одним API-процессом. Нет подтверждения email/восстановления пароля, общих каталогов нескольких аккаунтов, загрузки обложек, push-синхронизации, транскодирования или распределённого rate limiter. Развёртывание PostgreSQL/Compose/HTTPS требует отдельной проверки на целевой машине; автоматические интеграционные тесты используют H2.
