# Моя волна

Волна выбирает музыку из вашего доступного каталога. Она не подключается к Spotify/Яндекс Музыке и не скачивает композиции. Пустая библиотека даёт пустую очередь: сначала импортируйте собственные или разрешённые вам файлы.

## Воспроизводимый первый запуск сервера

1. Выполните шаги [SERVER_SETUP.md](SERVER_SETUP.md): `mvn -pl backend/server -am package`, запустите JAR с `--spring.profiles.active=dev`, проверьте `/api/v1/health`.
2. Создайте аккаунт, сохраните bearer token в `$headers` по примеру руководства.
3. Загрузите минимум 3 разных разрешённых аудиофайла через POST `/catalog/upload`. Проверьте, что GET `/tracks` возвращает реальные ID. У файлов должны быть полезные теги жанра/исполнителя; можно передать multipart `genre`, `artist` явно.
4. Задайте начальные предпочтения:

```powershell
$preference = @{ genres=@('Ambient','Jazz'); artists=@() } | ConvertTo-Json
Invoke-RestMethod "$api/preferences" -Method Put -Headers $headers -ContentType 'application/json' -Body $preference
$wave = Invoke-RestMethod "$api/wave?mode=MY_WAVE&limit=30" -Headers $headers
$wave | Select-Object score,reasons,@{Name='title';Expression={$_.track.title}}
```

5. Результат содержит `track`, числовой `score` и объяснения `reasons`. Откройте `/tracks/{id}/stream` с bearer заголовком через клиент. Это исходное аудио с Range-перемоткой.
6. Добавьте трек в избранное PUT `/favorites/{id}`. После реального прослушивания клиент отправляет POST `/history`: `{trackId,playedSeconds,completed,skipped}`. Нажатие play само по себе не считается прослушиванием.
7. POST `/feedback` `{trackId:"id",action:"MORE"}` или `LESS` изменяет выдачу. `DISLIKE` исключает трек; `BLOCK_ARTIST` исключает исполнителя. `UNBLOCK_ARTIST` снимает блокировку, `LIKE` заменяет прежний DISLIKE.
8. Повторите GET `/wave`, сравните score/reasons. Проверка автоматизирована в ServerIntegrationTest: Ambient поднимается по предпочтению, затем DISLIKE удаляет его из выдачи.

## Что учитывает первая версия

Content-based ранжирование использует выбранные жанры/исполнителей, метаданные, избранное, последние реакции, долю прослушивания и 1000 последних событий истории. Пропуск — слабый сигнал (-0.1 к профилю жанра/исполнителя), а не запрет. Недавние повторы за 24 часа получают штраф; число выбранных треков одного исполнителя снижает приоритет следующего. Алгоритм детерминирован для одинаковых сигналов, случайный shuffle не выдаётся за рекомендации.

`MY_WAVE` балансирует знакомое/новое; `DISCOVERY` повышает ещё не прослушанные треки; `FAVORITES` ограничивает очередь избранным; `FAMILIAR` — знакомым. `FOCUS`, `ENERGY`, `NIGHT`, `RELAX` повышают подходящие текстовые жанры. Аудиоэмбеддинги, BPM, анализ энергии и collaborative filtering пока не реализованы. Cold start сообщает об отсутствии сигналов в reasons. Без жанров/истории осмысленно сопоставить музыкальный вкус невозможно.

API выдаёт конечную порцию до 100 треков. Для продолжения клиент запрашивает следующую порцию после обновления истории, исключает текущий трек из активной очереди и обрабатывает отсутствие кандидатов. Маленькая библиотека закономерно повторяется. Нет скрытого внешнего источника новых композиций.

## Если волна не запускается

- `[]`: проверьте GET `/tracks`, наличие треков именно в этом аккаунте, реакции DISLIKE и блокировки; в FAVORITES сначала добавьте избранное.
- `401`: токен истёк/отозван, войдите снова.
- `400`: используйте один из точных mode: MY_WAVE, DISCOVERY, FAVORITES, FOCUS, ENERGY, NIGHT, RELAX, FAMILIAR.
- Сервер недоступен: health, адрес ПК вместо localhost на телефоне, Wi-Fi/Firewall, HTTPS-сертификат.
- Плохая релевантность: исправьте теги при явной загрузке, добавьте жанры/исполнителей и реакции; первая версия не умеет определять настроение по аудиосигналу.

Desktop также имеет автономную локальную волну; её коллекция не загружается на сервер автоматически. Чтобы продолжать те же серверные треки на телефоне, загрузите их явно и используйте один аккаунт. Локальный Desktop ID нельзя отправлять как серверный trackId.
