# Проверка подготовки Linux и магазинов: 0.8.0

Дата: 28 октября 2026. Исходники мобильного приложения: version 0.8.0 / build 13.

## Что изменилось

- Maven выбирает LWJGL natives для Linux вместо Windows; пути данных учитывают абсолютный XDG_DATA_HOME и прежнюю Linux-библиотеку.
- Добавлены Linux-скрипты запуска и jpackage для DEB/RPM/переносимого tar.gz, а также сборка Ubuntu 24.04 в GitHub Actions. DEB — основной формат, RPM пока дополнительный.
- Сохранены интерфейс и графика звука. В мобильный вход и настройки добавлен доступ к локальной политике и поддержке.
- Добавлены EAS-профили Google Play AAB, RuStore APK и App Store, локальная сборка AAB, запрет HTTP/тестовой подписи для магазинов, проверка production-подписи после внедрения EAS credentials.
- Подготовлены публичные страницы, карточки магазинов, инвентаризация данных и руководство. Публичный контакт: auralishelp@mail.ru.

## Выполнено на Windows

- Maven verify: **48 тестов**, 0 ошибок (audio core 12, Desktop 36). Проверены в том числе воспроизведение через FFmpeg, синхронизация, перенос базы, новые пути Linux и прежние пути Windows.
- Mobile: TypeScript, ESLint, **24 Node-теста**, 0 ошибок. Проверены локальный импорт/восстановление, волна, ссылки обложек, настройки графики, ограничения магазинных конфигураций и обновление signing-плагина.
- Bash: синтаксис двух Linux-скриптов проверен через `bash -n`. PowerShell: скрипт Android разобран без синтаксических ошибок.

- Собран настоящий **Android APK 0.8.0/code13 arm64** с тестовой подписью. Встроены JS/Hermes bundle, PCM-класс и GLView; проверены подпись v2 и zipalign 16 КБ. SHA256: `e032a98d53ee4e84d294fb743ba097b521cb810e2e504afc851de6ca1327f16c`.
- Проверены ELF LOAD-сегменты всех **26 .so** в этом APK: alignment не ниже 16 КБ и совпадение offset/vaddr по модулю 16 КБ. Это статическая проверка конкретного arm64 APK, не запуск на 16-КБ устройстве и не доказательство для будущего production AAB.
- Gradle release без production-ключа и без разрешения тестовой подписи фактически остановлен ожидаемой проверкой. Совместимость EAS credentials ещё требует подписанной облачной сборки владельца.
- Android и iOS Hermes export завершены успешно. Первые попытки в ограниченной среде не смогли записать временный файл компилятора; повторные запуски с обычными правами завершились успешно.
- Maven dependency tree с Linux-профилем разрешил Linux JavaFX и все три LWJGL native JAR; Windows target/lib не заменялся.

- Подготовлена отдельная iOS-иконка 1024×1024 RGB, без прозрачности; символ и цвета сохранены. HTML-страницы проверены на целостность локальных ссылок.
- Попытка iOS prebuild на Windows отклонена самим Expo CLI: генерация iOS-проекта нужна на macOS/Linux, компиляция — на macOS/Xcode. Успех Hermes export не означает успех iOS native-сборки.

## Linux: фактический результат

[Итоговый CI на Ubuntu 24.04 x86_64](https://github.com/Hollwestn/Auralis/actions/runs/40727004279) завершился успешно:

- **48 Java-тестов**: audio core 12, Desktop 36, 0 ошибок и пропусков.
- Создан настоящий `auralis_0.8.0_amd64.deb` со встроенным Java runtime.
- DEB установлен штатным apt, приложение запущено из `/opt/auralis/bin/Auralis` с отдельной тестовой библиотекой. Подтверждено видимое окно и сохранён настоящий скриншот: `AURALIS_LINUX_INSTALLED_WINDOW_OK`.
- [Артефакт с DEB, SHA256SUMS и скриншотом](https://github.com/Hollwestn/Auralis/actions/runs/40727004279/artifacts/12834055712) хранится до 4 ноября 2026; затем сборку можно повторить вручную. Копия DEB скачана в локальную `release/linux/` с проверкой SHA256 архива и пакета.

Первый прогон выявил тайм-аут повтора трека при ALSA null-выходе. В CI подключён виртуальный PulseAudio sink с нормальными часами воспроизведения; тест прошёл. Проверка установки дополнительно обнаружила отсутствие стандартного каталога desktop-меню в серверном образе runner; он создаётся при подготовке CI. Проверки сохранены, ни один тест не отключён. Финальная проверка использует Xvfb/Mesa и виртуальный звук: она не подтверждает звучание физических динамиков, драйверы каждого GPU или работу на всех дистрибутивах.

## Аудит мобильных зависимостей

`node-forge` обновлён с 1.4.0 до **1.4.2** через совместимый override. После установки повторно прошли TypeScript, ESLint, 24 теста, проверка audio-patch и Expo config. Версии Expo/React Native/Expo Audio не менялись. Явно закреплён `xml2js 0.6.2`: после обычной установки зависимостей версия 0.6.1 делала XML-свойства readonly и ломала Android prebuild. Прежняя запись lock-файла называла tarball 0.6.1 версией 0.7.0, которой нет в npm; она заменена корректной опубликованной версией. После исправления Android prebuild завершён успешно, добавлен регрессионный тест пустых Android resources.

`npm audit --omit=dev` после исправления: **3 high + 5 low, 0 critical**. Это два исходных замечания и их родительские зависимости: [zod](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5) через Expo CLI и [deepmerge](https://github.com/advisories/GHSA-gcqx-w48m-w2h4) через Expo config. Они не скрыты: исправление zod переходом 3 → 4 требует отдельной проверки совместимости CLI/ESLint; предложенный npm автоматический откат Expo 58 → 51 не применялся.

В 1608 sources Android packager source map собранного APK не найдены `node-forge` или `zod`; это свидетельство границы конкретного Android JS-бандла, а не гарантия отсутствия любых уязвимостей или проверка будущего iOS-архива. Перед магазинной публикацией повторите аудит и оценку toolchain после обновлений SDK.

Новый APK не запускался на физическом телефоне; предыдущие отчёты не подтверждают этот сценарий для 0.8.0. Три нативных PCM unit-теста Gradle использовал из кэша предыдущего запуска (код PCM в этой задаче не менялся); они не учитываются как новый прогон.

## Ограничения

На этом ПК нет установленного Linux/WSL-дистрибутива и macOS/Xcode. Linux DEB проверен в описанном CI; RPM, переносимый архив и ARM64 отдельно не запускались. iOS IPA и Swift-код требуют сборки и проверки на macOS/iPhone. Нет production-ключей Android, Apple-подписи и учётных данных магазинов: магазинные AAB/IPA здесь не выпускаются и не отправляются на модерацию. Test/Preview APK не предназначен для магазина.

Страницы политики подготовлены в `docs/`; их наличие в GitHub ещё не означает, что включён GitHub Pages. До публикации владелец проверяет публичные HTTPS-ссылки, анкеты данных, удаление аккаунта на тестовом сервере, лицензии контента, 16-КБ совместимость native-библиотек и сценарии на реальных устройствах. Актуальные команды — [руководство](../RELEASE_GUIDE.md).
