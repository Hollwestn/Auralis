# Запуск сервера Auralis

Для доступа из разных городов и сетей: [пошаговая инструкция VPS, DNS и HTTPS](SERVER_INTERNET_GUIDE.md), готовый `release/Auralis-Server-Internet.zip`.

Сервер не обязателен для локальной библиотеки Desktop и режима Mobile «Продолжить без аккаунта» в 0.6.2. Для общей коллекции на телефоне и компьютере загрузите музыку на сервер и войдите одним аккаунтом. Начальная библиотека пуста. [Локальный режим телефона](MOBILE_OFFLINE_GUIDE.md).

## Быстрая проверка на Windows без Docker

Нужна Java 25. В готовой поставке Maven и Docker не требуются:

```powershell
.\release\server\start-dev.ps1
```

По умолчанию сервер доступен на `http://localhost:8080`, данные сохраняются в `release/server/data`. Для телефона в той же доверенной Wi-Fi сети: `./release/server/start-dev.ps1 -Lan`; телефон использует IP компьютера вместо localhost, Android-тестовая сборка должна разрешать HTTP. Порт меняется через `-Port 8090`, остановка — Ctrl+C. Скрипт не меняет брандмауэр. Подробности подключения приведены ниже.

Для сборки из исходников дополнительно нужны JDK 25 и Maven 3.9+. Откройте PowerShell в корне Auralis и соберите сервер:

```powershell
mvn -pl backend/server -am package
```

Ожидается BUILD SUCCESS. Серверный JAR: `backend/server/target/auralis-server-0.1.0-SNAPSHOT.jar`. Maven впервые скачивает зависимости, нужен интернет.

Затем запустите:

```powershell
java -jar backend/server/target/auralis-server-0.1.0-SNAPSHOT.jar --spring.profiles.active=dev
```

В dev используется файловая H2 `./data/auralis`, музыка `./data/music`; БД и данные сохраняются после перезапуска. Ожидается `Started AuralisServer`. Порт по умолчанию слушает только 127.0.0.1.

Во втором PowerShell:

```powershell
Invoke-RestMethod http://127.0.0.1:8080/api/v1/health
```

Ожидается `status: ok`. Остановить сервер — Ctrl+C. Dev-профиль предназначен для локальной проверки; для постоянного сервера используйте PostgreSQL.

## Docker Compose и PostgreSQL

1. Установите и запустите Docker Desktop с Linux containers/WSL2. Выполните `docker version`, `docker compose version`. Сначала соберите JAR командой выше.
2. Скопируйте `infrastructure/.env.example` в `infrastructure/.env`. В редакторе замените `AURALIS_DB_PASSWORD` длинным случайным паролем. Файл не коммитьте.
3. Из корня:

```powershell
./infrastructure/start-server.ps1
```

Скрипт создаёт папки `infrastructure/import` и `backups`, собирает API image и запускает PostgreSQL 17 + API. Он никогда не удаляет данные. База наружу не публикуется, API на localhost:8080. Данные находятся в именованных Docker volumes `auralis_postgres_data` и `auralis_music_data`.

4. Проверка и логи:

```powershell
docker compose -f infrastructure/compose.yaml ps
docker compose -f infrastructure/compose.yaml logs --tail 100 api
Invoke-RestMethod http://localhost:8080/api/v1/health
```

Ожидаются запущенные db/api и health ok. При отказе соединения подождите миграцию Flyway и проверьте логи. Неверный пароль существующей БД нельзя исправить простой заменой `.env`: старый PostgreSQL volume уже содержит учётные данные; используйте прежний пароль или измените его в PostgreSQL. Не удаляйте volume для исправления пароля.

5. Остановка: `./infrastructure/stop-server.ps1`. Не добавляйте `down -v`: этот параметр удаляет данные.

## Аккаунт и явная загрузка музыки

В PowerShell 7 (или через клиент приложения):

```powershell
$api = 'http://127.0.0.1:8080/api/v1'
$registration = @{ email='you@example.com'; password='ВыберитеДлинныйПароль!'; displayName='Моё имя' } | ConvertTo-Json
$session = Invoke-RestMethod "$api/auth/register" -Method Post -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($registration))
$headers = @{ Authorization = "Bearer $($session.token)" }
Invoke-RestMethod "$api/catalog/upload" -Method Post -Headers $headers -Form @{file=Get-Item -LiteralPath 'C:\Music\song.flac'}
Invoke-RestMethod "$api/tracks" -Headers $headers
```

Подставьте существующий файл и собственный пароль. Максимальный файл 300 МБ, MP3/FLAC/WAV/OGG/M4A/AIFF. Повторный файл с тем же содержимым не дублируется. `-Form` отсутствует в Windows PowerShell 5.1: используйте PowerShell 7, curl.exe или загрузку из приложения. Токен храните приватно, не публикуйте вывод `$session`.

Для следующего входа: POST `/auth/login` с email/password. Токен живёт 30 дней. POST `/auth/logout` отзывает его. Удаление аккаунта: DELETE `/account`; это необратимо удаляет серверные записи и серверные копии музыки этого аккаунта.

## Разрешённый импорт папки

Импорт отключён по умолчанию. Пользовательский Desktop импорт остаётся локальным и сам музыку не отправляет. Чтобы явно разрешить серверный импорт:

1. Скопируйте разрешённую музыку в `infrastructure/import/MyMusic`.
2. Сначала зарегистрируйте свой аккаунт. Скопируйте его `id` из ответа регистрации или `GET /api/v1/account` с вашим bearer token. В `.env` задайте `AURALIS_IMPORT_ROOT=/import` и `AURALIS_IMPORT_ADMIN_USER_ID=полученный-uuid`.
3. Пересоздайте API: `docker compose -f infrastructure/compose.yaml up -d --force-recreate api`.
4. Войдите в аккаунт с этим ID. POST `/api/v1/catalog/import` с JSON `{"path":"MyMusic"}` и bearer token. Сервер читает только разрешённый root и копирует музыку в личный каталог. Символьные ссылки наружу запрещены. Ответ содержит tracks/rejected. Импорт выполняется в текущем запросе; для большой коллекции используйте подпапки, до 10000 файлов/запрос. Email не используется для выдачи доступа. После удаления аккаунта повторная регистрация создаёт другой ID: разрешение нужно явно перенастроить. Старый `AURALIS_IMPORT_ADMIN_EMAIL` не действует.

Без Docker задайте переменные окружения перед запуском Java: `$env:AURALIS_IMPORT_ROOT='C:\Music'`, `$env:AURALIS_IMPORT_ADMIN_USER_ID='полученный-uuid'`. Сначала проверьте права на эту папку. Никогда не задавайте корнем импорта весь диск или домашний каталог.

## Телефон в локальной сети

Для временной проверки в доверенной Wi-Fi сети задайте `AURALIS_HTTP_BIND=0.0.0.0` в `.env`, пересоздайте API. Узнайте адрес ПК через `ipconfig`, например `192.168.1.20`. Разрешите входящий TCP 8080 для частной сети в Windows Firewall. Телефон и ПК должны быть в одной сети; URL в приложении `http://192.168.1.20:8080`. `localhost` телефона обозначает телефон.

Для прямого dev-процесса Java вместо Compose добавьте `--server.address=0.0.0.0`. HTTP передаёт пароль/токен без шифрования; для постоянного доступа используйте следующий HTTPS вариант. Нативная мобильная сборка может требовать HTTPS согласно настройкам ОС/приложения.

## VPS и HTTPS

1. Подготовьте Linux VPS с Docker Engine + Compose plugin. Создайте DNS A/AAAA для собственного домена, направив его на VPS. Откройте входящие TCP 80/443, UDP 443 опционально; 5432 не открывайте. 8080 оставьте привязанным к localhost.
2. Перенесите проект с собранным JAR на сервер; создайте infrastructure/.env с паролем и `AURALIS_DOMAIN=music.your-domain.com`.
3. В каталоге infrastructure выполните `mkdir -p import backups`, затем `docker compose --profile https up --build -d`.
4. Caddy автоматически получает TLS-сертификат для домена. Проверьте `https://music.your-domain.com/api/v1/health`. При сбое сертификата проверьте DNS, NAT, 80/443 и `docker compose logs https`.
5. На ПК и телефоне укажите этот HTTPS URL без `/api/v1`; клиент добавляет API-префикс. Используйте один аккаунт, добавьте музыку явной загрузкой.

`AURALIS_DOMAIN=localhost` использует локальный сертификат Caddy, которому телефон автоматически не доверяет. Для телефона используйте публичный домен с действующим сертификатом. Сам сервер Java HTTP находится за Caddy в закрытой Docker сети.

## Резервные копии и восстановление

В Windows запустите `./infrastructure/backup.ps1`. Он останавливает API на время обеих копий, делает `pg_dump -Fc` в bind mount и tar музыкального volume, затем запускает API обратно через finally. Сохраните `.env` отдельно в защищённом месте. Архивы `infrastructure/backups/database-TIMESTAMP.dump` и `music-TIMESTAMP.tar.gz` перенесите на другой диск; они содержат личные данные.

На Linux те же действия: `docker compose stop api`; `docker compose exec -T --user 0 db pg_dump -U auralis -d auralis -Fc -f /backups/database.dump`; `docker compose run --rm --no-deps --user 0 --entrypoint tar -v "$PWD/backups:/backups" api -czf /backups/music.tar.gz -C /app/data .`; `docker compose start api`.

Восстанавливайте в отдельном тестовом развёртывании, сначала запустите db и остановите api. Положите выбранную пару архивов в backups. Выполните `docker compose exec -T db pg_restore -U auralis -d auralis --clean --if-exists /backups/database-TIMESTAMP.dump`; это заменяет записи целевой БД. Далее `docker compose run --rm --no-deps --user 0 --entrypoint tar -v "ABSOLUTE_PATH_TO_BACKUPS:/backups" api -xzf /backups/music-TIMESTAMP.tar.gz -C /app/data`, затем `docker compose run --rm --no-deps --user 0 --entrypoint chown api -R 10001:10001 /app/data`. Запустите api, проверьте health, каталог и проигрывание. Подставьте реальный абсолютный путь. Не выполняйте восстановление поверх рабочей БД без свежей копии и осознанного выбора цели.

## Обновления и границы проверки

Сделайте резервную копию, получите новую версию исходников, выполните Maven package/tests, затем `docker compose up --build -d api`. Flyway применит новые миграции. Для отката сначала оцените совместимость миграций; не заменяйте БД вслепую.

Проверены полная Java25 Maven verify (52 теста), H2/Flyway, авторизация, изоляция аккаунтов, реальная WAV-загрузка и HTTP Range, библиотека, история, синхронизация и рекомендации. Дополнительно собранный JAR действительно запущен на localhost:18080, настоящий Desktop ServerClient выполнил 21 HTTP-проверку с двумя сессиями одного аккаунта и отдельным чужим аккаунтом. SHA-256 скачанного WAV совпал с оригиналом. См. [SERVER_TEST_REPORT.md](SERVER_TEST_REPORT.md) и `docs/verification/server-http.json`.

На Windows сервер использует стандартный Tomcat NIO2, Desktop — HttpURLConnection. Это позволяет работать в окружениях, где JDK NIO Selector не может создать локальный Unix-domain wakeup socket; остальные ОС сохраняют обычный Tomcat NIO. TLS-проверка остаётся стандартной, редиректы Desktop не пересылают bearer token.

В этом окружении Docker отсутствует: Compose/PostgreSQL/Caddy/backup/restore не запускались. Проект — рабочая первая реализация для личного сервера, без распределённой инфраструктуры, восстановления пароля/email-проверки и push-синхронизации. Для публичного сервиса понадобятся отдельный аудит, ограничение регистрации, мониторинг, политика хранения и тест восстановления.

## Действия в Desktop

На странице «Сервер» войдите в общий аккаунт. «Загрузить файлы» открывает системный выбор: только выбранные вами файлы отправляются в личный серверный каталог. Сканирование локальной папки и синхронизация файлы автоматически не отправляют. «↓ Слушать» сохраняет и проверяет офлайн-копию, затем запускает локальный проигрыватель.

Кнопки ♥, «+ Плейлист» и «Плейлисты» меняют общую серверную коллекцию. «История» показывает серверные события. Выберите режим и «Запустить волну», чтобы увидеть объяснения рекомендаций. «↓ В локальные» у плейлиста явно скачивает его музыку; при переносе в локальную SQLite повторные ссылки на один трек объединяются.

«↑ Коллекция» сопоставляет изменения избранного связанных треков, передаёт изменённые плейлисты, ещё не отправленные события истории (до 100000 локальных записей) и предпочтения с этого ПК. Нетронутый локальный кэш не стирает новый лайк с телефона. Плейлист с хотя бы одним только локальным файлом пропускается целиком. При конфликте плейлиста сохраняются отдельные версии, без перезаписи чужих изменений. Никакой неявной загрузки аудио. «↓ Плейлисты и избранное» явно скачивает музыку серверных плейлистов/избранного, импортирует их и историю уже доступных треков, загружает предпочтения; основной экран уведомляется для обновления кэша. Несохранённое локальное содержимое плейлиста сохраняется отдельной копией перед приёмом серверного варианта.

«↑ Позиция» сохраняет всю очередь серверных треков, выбранное вхождение (включая повторные), позицию, play/pause, shuffle/repeat и настройки. Если в очереди есть только локальный файл, операция целиком остановится с объяснением: сначала явно загрузите его либо уберите из очереди. «↓ Продолжить» скачивает недостающие копии всей очереди перед восстановлением, включая первое получение. Версионный конфликт позиции обрабатывается повторным чтением и одной попыткой записи с сохранением неизвестных полей другого клиента. Маппинг копий/истории изолирован по адресу сервера и аккаунту.

Синхронизация выполняется этими явными действиями, push пока нет. Новые клиенты передают version плейлиста; старый формат без неё остаётся совместимым, но не защищён от перезаписи. Удаление локального плейлиста само по себе не удаляет серверный. История с eventId сохраняет исходную дату и безопасно повторяется после потерянного подтверждения; импорт на ПК и отметки дедупликации атомарны. Ограничения и текущие доказательства новых исправлений — [SYNC_INTEGRITY_AUDIT.md](SYNC_INTEGRITY_AUDIT.md). До повторной упаковки прежний EXE не считается сборкой этих изменений.

Стек Java25/Spring Boot3.5.16 выбран по [официальной совместимости Spring](https://docs.spring.io/spring-boot/3.5/system-requirements.html). Парсер [Jaudiotagger](https://github.com/VinylMusicPlayer/jaudiotagger) используется только для чтения метаданных/проверки файла; оригинал не переписывается.
