# Auralis на Android

Приложение находится в `apps/mobile`: React Native 0.88, Expo SDK 58 и TypeScript. Оно использует настоящие серверные данные и отдельный нативный аудиоплеер. Результат сборки и проверки устройства перечислены в `MOBILE_TEST_REPORT.md`; наличие исходников или JS-бандла не означает наличие APK.

Исправление мгновенного вылета выпуска 0.5.1: [подробности и установка 0.6.1](ANDROID_STARTUP_FIX.md).

## Установка готового APK

1. Готовый `release/android/Auralis-Android-Test.apk` — автономная arm64-сборка для Android7+ с проверенной тестовой Android-подписью. SDK и Node для её установки не нужны. `Auralis-Android.apk` предназначен для сборки с вашим release-ключом. Пустых файлов вместо APK проект не создаёт.
2. Скопируйте настоящий APK на телефон. Откройте его через файловый менеджер и разрешите установку этому файловому менеджеру. После установки разрешение можно выключить.
3. Запустите Auralis. Установленный APK содержит JS/Hermes-бандл, запуск Metro и установка Node на телефон не нужны.
4. Для музыки на телефоне выберите **«Продолжить без аккаунта»** → **«Добавить музыку с телефона»**. Сервер и регистрация не нужны. [Полная инструкция локального режима 0.6.2](MOBILE_OFFLINE_GUIDE.md).
5. Для серверной коллекции укажите адрес своего сервера, например `https://music.example.com`, без `/api/v1`. Создайте аккаунт или войдите тем же аккаунтом, что на компьютере. Музыка появляется после явного добавления файлов на сервер; локальная папка ПК автоматически не отправляется.

Для подключения через интернет нужен корректный HTTPS-сертификат. Адрес `localhost` на телефоне указывает на сам телефон. В локальной сети используйте IP компьютера, например `http://192.168.1.50:8080`; HTTP работает только в сборке, явно собранной с `-AllowLocalHttp`. На Android-эмуляторе адрес компьютера обычно `http://10.0.2.2:8080`.

## Сборка на Windows

Нужны Node.js 24, JDK 17 или 21, Android SDK и интернет для зависимостей. Java 25 остаётся стеком Desktop; Android Gradle использует отдельный JDK.

1. Установите [Android Studio](https://developer.android.com/studio). Через SDK Manager установите Command-line Tools, Platform-Tools, Android SDK Platform **37.0**, Build-Tools **37.0.0** и **36.0.0**, платформу **36** для unit-тестов Expo Audio, NDK **27.1.12297006**, CMake **3.22.1**.
2. Укажите путь к SDK в PowerShell:

   ```powershell
   $env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
   $env:JAVA_HOME = 'C:\Program Files\Java\jdk-17'
   ```

   Для уже подготовленного локального SDK проекта можно указать абсолютный путь к `.runtime/android-sdk`. Список пакетов определяется реальным SDK Manager: пакет платформы называется `platforms;android-37.0`, не `platforms;android-37`.

3. Из корня проекта выполните:

   ```powershell
   .\scripts\build-android.ps1 -AllowLocalHttp
   ```

   Скрипт устанавливает зависимости из lockfile, применяет проверяемое расширение Expo Audio, запускает TypeScript, ESLint и тесты, затем собирает `assembleRelease` с явно разрешённой тестовой подписью. По умолчанию собирается `arm64-v8a`, подходящая большинству современных телефонов. Для эмулятора используйте `-Architecture x86_64`, для нескольких архитектур — `-Architecture all`.
4. Ожидаемый результат: непустой `release/android/Auralis-Android-Test.apk` и его SHA-256. Скрипт проверяет внутри APK `AndroidManifest.xml`, `classes.dex`, встроенный `assets/index.android.bundle`, а также настоящий DEX на собственный PCM-класс и метод `setSpectrumEnabled`. В package.json принудительно включена сборка Expo Audio из исходников; готовый AAR без расширения не принимается.

Корневой скрипт по умолчанию включает тестовую подпись. Его параметр `-Production` включает собственный release-ключ; `-SkipDependencies` пропускает npm ci. Внутренний `apps/mobile/scripts/build-android.ps1` принимает `-TestApk` явно и использует имя `-SkipInstall`. При повторной проверенной сборке разрешён `-SkipTests`. Gradle ограничен двумя worker-процессами. Первая нативная сборка скачивает несколько гигабайт SDK/NDK/Gradle и может занимать значительное время.

## Подпись для распространения

Создайте собственный keystore через Android Studio или `keytool`; сохраните его резервную копию отдельно от репозитория. Передайте сборщику переменные `AURALIS_UPLOAD_STORE_FILE`, `AURALIS_UPLOAD_STORE_PASSWORD`, `AURALIS_UPLOAD_KEY_ALIAS`, `AURALIS_UPLOAD_KEY_PASSWORD`, затем запустите корневой скрипт с `-Production` и без `-AllowLocalHttp`. Пароли не должны попадать в Git или журналы. Без ключей release-сборка останавливается. Для обновления установленного приложения нужен тот же ключ; версия с другой подписью потребует удаления предыдущей установки, что удалит её локальные загрузки.

## Проверка музыки и фонового режима

1. Добавьте несколько собственных треков на сервер. Потяните главную страницу вниз.
2. Запустите трек. Проверьте паузу, перемотку и переход на следующий трек. Очередь обслуживается нативным `AudioPlaylist`.
3. Заблокируйте экран более чем на три минуты. Проверьте продолжение, системное уведомление и кнопки предыдущего/следующего трека. При отключённом параметре фонового воспроизведения в настройках фоновая работа намеренно отключается.
4. Подключите Bluetooth-наушники, проверьте воспроизведение и аппаратные кнопки. Отключение наушников должно останавливать звук.
5. В меню трека выберите «Скачать для офлайна». Отключите сеть и откройте «Моя музыка → Скачано». Офлайн доступны только полностью скачанные файлы этого аккаунта и сервера.
6. Поставьте лайки, укажите жанры в настройках, запустите «Мою волну». Она выбирает треки из вашего каталога; внешний музыкальный сервис не подключён.
7. Остановите трек на ПК, сохраните его позицию. На телефоне нажмите «Продолжить на этом устройстве». Если файла нет в серверной библиотеке, приложение объяснит недоступность.
8. Проверьте восемь тем, визуализации, отключение эффектов и системное уменьшение движения. Визуальные параметры синхронизируются с Desktop.

## Звучание и визуализации

В плеере работают громкость, скорость, повтор одного трека/очереди и перемешивание. Эквалайзер и монтаж выполняются в Desktop; мобильный интерфейс не изображает несуществующий DSP.

«Визуальный фон главной» и «Фоновое воспроизведение» — независимые переключатели. Первый выключает GPU-фон главной страницы; второй разрешает продолжение музыки при блокировке экрана. Переключение визуального фона на ПК не меняет фоновое аудио телефона.

Визуализации используют Expo GL и восемь разных GLSL-режимов. Аудиореакция получает 32 полосы настоящего FFT декодируемого PCM собственного плеера. Микрофон не используется. Для этого применяется воспроизводимое нативное расширение `scripts/patch-expo-audio.cjs`, привязанное к Expo Audio 58.0.9; при обновлении версии скрипт требует пересмотра. В Expo Go этого расширения нет: для проверки аудиореакции требуется собственный APK.

В 0.6.0 Reactive Album Art и остальные прежние дополнительные сцены удалены. Новые режимы и настройка палитр описаны в [GRAPHICS_060.md](GRAPHICS_060.md). Обложки треков в самом плеере сохранены.

## Типичные ошибки

- `Failed to fetch`: проверьте адрес, HTTPS, доступность порта и входящий доступ в брандмауэре Windows. Для тестовой HTTP-сборки используйте `-AllowLocalHttp` и частный IP.
- `401`: токен истёк или отозван. Выйдите в настройках и войдите снова.
- Трек не звучит: проверьте файл и поддержку формата устройством. Скачивание не преобразует аудиокодек.
- Node `fs.cpSync EIO` в OneDrive: Expo 58 по умолчанию пересоздаёт native-папки. В проекте поставляются сгенерированные папки; используйте `prebuild --no-clean`, как делает скрипт. При сохраняющейся ошибке скопируйте проект в короткий путь вроде `C:\Auralis`.
- Ошибка native-инструментов на пути с кириллицей: используйте каталог с латинскими буквами. Не отключайте антивирус и системную защиту.
- `SDK location not found`: исправьте `ANDROID_HOME`. Смотрите конкретный пакет, названный Gradle, в SDK Manager.
- Нестабильные FPS: выберите Eco или 15 FPS, уменьшите интенсивность либо выключите визуализацию. Измеренная производительность на конкретном телефоне требует проверки на этом телефоне.

Протокол фактических проверок: [MOBILE_TEST_REPORT.md](MOBILE_TEST_REPORT.md).

## Windows: кириллица и длинные пути

Для нативной сборки нужен короткий физический путь с латинскими буквами, например `C:\work\Auralis`, а не OneDrive-папка с кириллицей. Исходный проект можно оставить на месте. Скопируйте его в свой каталог сборки, исключив `.runtime`, `release`, `.git`, `.idea`, `node_modules`, Android `build/.gradle/.cxx` и Maven `target`. Затем выполните `npm ci` и сборку из копии. Готовый APK верните в `release/android` основного проекта. Сборщик теперь сразу объясняет это ограничение вместо долгой неудачной C++-компиляции.

В фактической проверке использовалась отдельная короткая приватная копия мобильного проекта в `C:\ProgramData\aa…`, с отключённым наследованием ACL и доступом только текущему пользователю и SYSTEM. Каталог временный; его удаление не затрагивает исходный проект. Псевдоним `subst` сам по себе недостаточен: автолинковка Node возвращает физический путь, а смешение дисков приводит к ошибке Kotlin codegen.

SDK CMake 3.22.1 поставляет старый Ninja 1.10.2. Для новых codegen-модулей он останавливается на пути длиннее 260 символов. Скрипт сборки обновляет только `ANDROID_HOME/cmake/3.22.1/bin/ninja.exe` до официального **1.13.2** с сохранением прежнего файла. Загрузка закреплена SHA-256 ZIP:

```text
07FC8261B42B20E71D1720B39068C2E14FFCEE6396B76FB7A795FB460B78DC65
```

Ручной запуск из корня проекта:

```powershell
.\apps\mobile\scripts\install-windows-ninja.ps1 -SdkRoot $env:ANDROID_HOME
```

Источник: [официальный Ninja 1.13.2](https://github.com/ninja-build/ninja/releases/tag/v1.13.2). Конфигурационный Expo plugin добавляет `CMAKE_OBJECT_PATH_MAX=240` для сокращения объектных путей; [документация CMake](https://cmake.org/cmake/help/v3.22/variable/CMAKE_OBJECT_PATH_MAX.html). Старый Ninja сохраняется рядом с суффиксом `.original.exe`. Глобальный PATH и реестр сборщик не меняет. В проверенной системе Windows `LongPathsEnabled=1` уже был включён.

Если Java сообщает `Unable to establish loopback connection`, используйте существующий короткий ASCII-каталог для временных сокетов, например:

```powershell
New-Item -ItemType Directory C:\work\java-temp -Force
$env:JAVA_TOOL_OPTIONS = '-Dfile.encoding=UTF-8 -Djdk.net.unixdomain.tmpdir=C:/work/java-temp'
```

Создавайте его в доступном вам приватном рабочем каталоге. Это настройка локальных путей; TLS и системная защита остаются включёнными.

Путь самого SDK/CMake также должен быть латинским. При имени пользователя с кириллицей выберите, например, отдельный `C:\AndroidSdk` при установке SDK, вместо `%LOCALAPPDATA%\Android\Sdk`. В проверенной сборке только CMake был скопирован в приватную ASCII-папку, а Android `local.properties` содержал `cmake.dir=C:/.../cmake`. Это [штатное локальное свойство Android Gradle](https://developer.android.com/build). Файл local.properties привязан к машине и не переносится как общая конфигурация проекта.
