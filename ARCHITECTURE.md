# Архитектура Auralis

Auralis 0.1 — первая проверяемая сборка собственной музыкальной платформы. Подробные фактические результаты находятся в `TEST_REPORT.md`. Полный объём исходного технического задания шире этой версии; незавершённые пункты перечислены в `ROADMAP.md`.

## Выбор технологий

- **Desktop:** Java 25, JavaFX 25.0.2, FXML, CSS, Maven. Отдельный Windows UI; локальная музыка работает без аккаунта и сети. JavaFX поддерживает реальное воспроизведение и десятиполосный EQ. [Официальная документация](https://openjfx.io/openjfx-docs/).
- **Локальные данные:** SQLite с миграцией схемы, стабильными идентификаторами и плейлистами. Метаданные и обложки сохраняются отдельно; оригиналы остаются на месте.
- **Аудио:** FFmpeg/FFprobe как отдельные процессы с аргументами через `ProcessBuilder`, ограниченным выводом и таймаутами. Потоковый анализ PCM не требует загружать песню целиком в память. JSON проекта содержит монтажные решения, экспорт создаёт отдельный файл.
- **Server:** модульный монолит Spring Boot 3.5.16, Java 25, PostgreSQL, JDBC/Flyway. HTTP Range подходит для первого независимого каталога без инфраструктуры HLS. H2 используется только для разработки и интеграционных тестов. [Совместимость Spring Boot 3.5](https://docs.spring.io/spring-boot/3.5/system-requirements.html).
- **Mobile:** React Native, TypeScript, Expo Router и нативное `expo-audio`. Это отдельный интерфейс с системным управлением аудио. Актуальные зафиксированные версии см. `apps/mobile/package.json` и lockfile.

## Границы модулей

```text
apps/desktop → audio/core → SQLite + FFmpeg
apps/desktop → backend/server REST API
apps/mobile  → backend/server REST API
backend/server → PostgreSQL + личное файловое хранилище
infrastructure → Docker Compose + Caddy HTTPS
```

`audio/core` не зависит от JavaFX. Он содержит библиотеку, рекомендации, монтаж и LRC parser. `PlaybackService` владеет единственным основным JavaFX MediaPlayer и освобождает его при переключении трека. Предпрослушивание редактора использует отдельный MediaPlayer. Контроллеры управляют UI; сканирование, HTTP, декодирование и экспорт уходят в виртуальные потоки. Обновления интерфейса возвращаются через `Platform.runLater`.

## Данные и синхронизация

Локальная SQLite не является копией всей серверной БД. Импортированные файлы доступны только на этом ПК. Серверные композиции имеют отдельные UUID и владельца. Явно скачанная серверная композиция связывается с локальной по сохранённому соответствию идентификаторов. Для переноса позиции на другое устройство нужен серверный track ID. У локального файла без серверной копии такого ID нет; интерфейс объясняет недоступность.

Состояние `/sync` имеет версию. Конкурирующее изменение возвращает конфликт; клиент должен перечитать его. Плейлисты, история, избранное и предпочтения имеют самостоятельные ресурсы API. Точное покрытие Desktop/Mobile смотрите в отчёте, а не выводите из наличия endpoint.

## Безопасность и эксплуатация

Сервер хранит хеши паролей и хеши непрозрачных токенов. Музыкальные пути не принимаются непосредственно в streaming URL. Запросы проверяют владельца и ограничивают частоту. Импорт серверной папки выключен по умолчанию и ограничен настроенным корнем. Никаких публичных музыкальных источников и DRM обходов нет.

Desktop не сохраняет пароль/токен на диск. Mobile использует SecureStore; файлы офлайн-каталога изолированы по пользователю. HTTPS завершает Caddy. Резервная копия PostgreSQL должна сопровождаться копией музыкального хранилища.

## Расширение

Рекомендатель возвращает score и объяснения. В первой версии используются жанры, исполнители, реакции и история. BPM/энергия/настроение не выдумываются. Интерфейс ранжирования допускает дополнительные признаки и модели без обязательных платных API. Для студии параметрический realtime DSP потребует отдельного движка; возможности FFmpeg экспорта и JavaFX playback описаны раздельно в `AUDIO_ENGINE.md`.

## Black Hole 0.5.1 / 4K

Black Hole — процедурный трёхмерный объём с трассировкой искривлённых лучей через аккреционный диск. Видео не используется. Desktop может отдельно рендерить framebuffer3840×2160, сохраняя размер в интерфейсе и пропорции сцены; Mobile использует тот же GLSL с адаптивным разрешением. Описание и фактические проверки: [BLACK_HOLE_4K.md](docs/BLACK_HOLE_4K.md), [TEST_REPORT.md](TEST_REPORT.md).
